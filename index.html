Que tu web se vea bien en el móvil y en el ordenador

Una misma página tiene que caber en una pantalla de 320 píxeles y aprovechar una de 1600. Eso se llama diseño adaptable (responsive) y se hace con tres piezas: el meta viewport, las media queries y un maquetado flexible. Aquí lo ves explicado y funcionando.

Esto mide tu ventana ahora mismo. Estrecha el navegador (o gira el móvil) y mira cómo cambia.

1 La idea en tres piezas

El móvil no es «un ordenador pequeño»: es otra pantalla, con otro ancho, otro dedo y a veces sin ratón. Para que la web funcione en las dos hay que dejar de pensar en píxeles fijos y pensar en reglas.

1 · Que el móvil no haga zoom

Una línea en el <head> le dice al móvil «usa el ancho real de la pantalla».

<meta name="viewport"
      content="width=device-width,
               initial-scale=1.0">

2 · Que el CSS pregunte

Las media queries aplican estilos solo si la pantalla mide más o menos de X.

@media (min-width: 640px) {
  .rejilla { grid-template-columns:
             repeat(2, 1fr); }
}

3 · Que nada tenga ancho fijo

Flecos, rejillas y textos en %, rem y fr: se adaptan solos.

.rejilla {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(220px, 1fr));
}

Si tu pantalla es más estrecha que el marco, arrastra el marco hacia un lado para verlo completo.

El CSS que hace esto

Tres media queries, una detrás de otra. Se leen de arriba abajo y gana la última que se cumpla:

/* móvil: una columna, menú ☰ */
@media (max-width: 620px) {
  .rejilla { grid-template-columns: 1fr; }
  .menu { display: none; }
  .burger { display: block; }
}

/* tableta: dos columnas */
@media (min-width: 621px) {
  .rejilla { grid-template-columns: 1fr 1fr; }
}

/* escritorio: tres columnas y barra lateral */
@media (min-width: 901px) {
  .rejilla { grid-template-columns: repeat(3, 1fr); }
  .lateral { display: block; }
}

3 El meta viewport, sin él no hay nada

Si te olvidas de esta línea, el móvil simula una pantalla de 980 píxeles y encoge la web para que quepa: se ve todo diminuto y las media queries nunca se cumplen. Es el error número uno. 

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mi web</title>
</head>
  • width=device-width: el ancho de la página es el ancho físico de la pantalla.
  • initial-scale=1.0: sin zoom inicial. La persona puede hacer zoom con los dedos; no se lo quites.

⚠️ Nunca uses user-scalable=no ni maximum-scale=1: impiden ampliar y dejan la página inutilizable para quien ve poco.

4 Media queries: el CSS que pregunta

Una media query es un if de CSS: «si la pantalla mide al menos 640 píxeles, aplica esto». Hay dos formas de escribirla y conviene elegir una:

Mobile-first (recomendado)

Escribes primero el móvil, sin media query, y vas añadiendo con min-width.

.rejilla { grid-template-columns: 1fr; }

@media (min-width: 640px) {
  .rejilla { grid-template-columns: 1fr 1fr; }
}

Menos CSS, más fácil de mantener: el caso complicado (pantalla pequeña) es el que se escribe primero.

Desktop-first

Escribes primero el ordenador y luego deshaces con max-width.

.rejilla { grid-template-columns: repeat(3, 1fr); }

@media (max-width: 639px) {
  .rejilla { grid-template-columns: 1fr; }
}

Vale si la web ya existía, pero acabas con más excepciones.

5 Deja de medir en píxeles fijos

El px no se entera de nada: si el contenedor crece, el texto sigue igual. Las unidades relativas sí. Mueve el mando y compara los tres párrafos, que tienen el mismo texto pero distinta unidad.

Esto mide 16px: fijo, no cambia nunca.

Esto mide 1.4em: crece con el contenedor.

Esto mide 1rem: depende de la raíz de la página.

p { max-width: 65ch; }

6 Que la maqueta se reordene sola

Con flexbox y grid no hay que calcular posiciones: se les dan reglas y ellos reparten. Este es el patrón que resuelve el 90 % de los casos:

Fila que se convierte en columna

.fila {
  display: flex;
  flex-wrap: wrap;   /* si no caben, bajan */
  gap: 12px;
}
.fila > * { flex: 1 1 220px; }

Sin media query: los hijos bajan solos cuando no caben. Ideal para botones y tarjetas.

Rejilla que cambia de columnas

.rejilla {
  display: grid;
  gap: 16px;
  grid-template-columns:
    repeat(auto-fit, minmax(220px, 1fr));
}

auto-fit decide cuántas columnas caben. De 1 a 4, sin escribirlo.

Consejo de orden: primero el flujo normal (todo en una columna), después flex para filas, después grid para rejillas, y las media queries al final, solo para lo que no se resuelve solo.

7 Imágenes y vídeos que no se desbordan

Una imagen de 600 píxeles dentro de un móvil de 360 se sale de la pantalla. Se arregla con una regla de dos líneas. Mueve el mando y compara las dos cajas: 

/* la regla que arregla el 90 % de los desbordes */
img, video, iframe {
  max-width: 100%;
  height: auto;      /* mantiene la proporción */
  display: block;
}

/* y si quieres que llene su caja sin deformarse */
img { object-fit: cover; }

8 Dedos, no punteros

En un móvil no hay ratón: hay un dedo de unos 9 mm. Un enlace de 12 píxeles de alto es una trampa. La recomendación general es que lo que se pulsa mida al menos 44 × 44 píxeles y esté separado de lo de al lado.

un enlace diminuto

Pulsa el botón para ver el área real de cada elemento.

/* objetivos cómodos para el dedo */
button, a.boton {
  min-height: 44px;
  min-width: 44px;
  padding: 12px 18px;
}

/* no bases la información en :hover: en el móvil no existe */
@media (hover: none) {
  .tarjeta:hover { transform: none; }
}

9 Cómo comprobarlo antes de publicar

  1. Modo dispositivo en el navegador. Con la web abierta pulsa F12 y el icono de móvil (Ctrl + Shift + M). Elige «iPhone SE» (375 px) y «iPhone grande»: ahí se ven los fallos de verdad.
  2. Prueba los extremos. 320 px (el móvil más estrecho que existe) y 1440 px. Si aguanta los dos, aguanta todo lo de en medio.
  3. Sin ratón. En el modo dispositivo, comprueba que todo lo importante se alcanza con el dedo y que nada depende de :hover.
  4. En un móvil de verdad. Lo mejor: publica la página y ábrela en tu teléfono. Si estás en la misma wifi, algunos servidores locales te dejan entrar por la IP del ordenador (http://192.168.1.XX:8000).
  5. Gira la pantalla. Horizontal y vertical. Que nada se corte ni se solape.

11 Chuleta adaptable

/* 1. En el head, siempre */
<meta name="viewport" content="width=device-width, initial-scale=1.0">

/* 2. Que nada se salga */
* { box-sizing: border-box; }
img, video, iframe { max-width: 100%; height: auto; }

/* 3. Base móvil, luego crece */
.rejilla { display: grid; gap: 16px; grid-template-columns: 1fr; }
@media (min-width: 640px) { .rejilla { grid-template-columns: 1fr 1fr; } }
@media (min-width: 960px) { .rejilla { grid-template-columns: repeat(3, 1fr); } }

/* 4. Texto que respira */
h1 { font-size: clamp(1.6rem, 4vw + 1rem, 3rem); }
p  { max-width: 65ch; }

/* 5. Dedos cómodos */
button, .boton { min-height: 44px; padding: 12px 18px; }

/* 6. Respetar al sistema */
@media (prefers-color-scheme: dark)  { :root { --fondo: #131a17; } }
@media (prefers-reduced-motion: reduce) { * { transition: none !important; } }

Con esto ya puedes coger cualquier página y hacerla funcionar en un celular y en un ordenador. El siguiente paso natural: el proyecto completo (index.html + estilos.css + script.js), con formulario, tarjetas y modo oscuro, y su guía paso a paso.
